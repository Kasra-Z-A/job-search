    01 / Search

    How a search works

    The job index is built once per data snapshot. Five steps run for every message.

    Every posting on Himalayas comes with labels for seniority, category, eligible countries, contract type and salary. The search uses these labels for the hard requirements in a message and the posting text for everything else. Claude Haiku turns the message into label filters, the filters remove jobs that don't qualify, and the remaining jobs are ranked by how similar their text is to the message.

    How filters are chosen

    Haiku reads the message for seniority, category, eligible countries, contract type and a minimum salary. It can only choose values that exist in the index, so a filter never asks for a category no job has.

    Salaries are converted to US dollars before they are compared. In a follow-up message, Haiku edits the previous filters instead of starting over.

    How results are ordered

    Jobs that meet every filter come first, sorted by how close their vector is to the message's. A vector is a list of numbers from an embedding model; texts with similar meaning get similar vectors.

    Jobs with a missing label, such as a posting with no salary, cannot be ruled out. They follow as possible matches. Haiku reads the top 20 descriptions and recommends up to six, with a reason for each.

    Haiku refers to jobs by number only. Titles, links and details come from the index, and any amount in a reason is checked against the data, so a recommendation cannot point to a job that doesn't exist.

    02 / Evaluation

    Search accuracy

    Share of the top 10 results that meet every criterion of the search (precision@10), averaged over 1,464 test searches.

    03 / Test method

    How test searches are made

    Each test search starts from the labels of a real job, for example senior · Developer · open to Canada · at least $140k.

    One LLM call writes the labels as a request a person might type. A second call checks that the request asks for exactly those criteria. A result counts as correct if its labels meet every criterion, which gives an answer key for every search without labelling jobs by hand.

    Typos and casual wording barely change the score: 40 such searches score 99.7%, against 100% for the same searches written cleanly.

    04 / Interpretation

    What the score measures

    The assistant filters on the same labels the test criteria come from. When Haiku chooses the right filters, every result is correct, so the 99% mainly measures that step. It gets the filters exactly right for 98% of test searches.

    Most errors involve "management", which Himalayas uses both as a category and as a seniority level.

    The test does not check how well a job fits within a broad category: any Developer job counts as correct for a request about backend Python. The ranking and the recommendations are not measured yet.

    05 / Without labels

    Searching postings without labels

    Many job sites only have the posting text. To test this case, an LLM read each description and recorded the seniority, category, countries, contract type and salary it states. The assistant then filtered on those values instead of the Himalayas labels.

    Precision rises from 17% with meaning search alone to 41%, but stays far below 99%. Descriptions often leave things out: of the jobs with a salary, 85% state it in the text. About half say where they hire, and a third state the contract type.

    06 / Limitations

    What is not tested yet

    • The test searches are written and checked by LLMs. Searches written by people have not been tested yet.
    • Only the first message of a conversation is tested, not follow-ups or the written recommendations.
    • The job board's labels contain errors: a manual check of 48 seniority labels found 88% correct. The test treats the labels as correct, so these errors do not lower the score.
