    System

    How a search runs

    The job index is built once per data snapshot. It has one row per job with two parts: the labels from the Himalayas fields (seniority, category, countries, contract type, salary) and a vector embedded from the title and description. For each message, Haiku converts it into filters, the labels decide which jobs qualify, the vectors put those jobs in order, and Haiku picks the best of them.

    Evaluation

    How the search is evaluated

    Each test search is generated from a real job's fields, for example senior · Developer · open to Canada · at least $140k. One LLM rewrites the fields as a plain-language request, and a second LLM checks that the request matches them. Because the criteria are known, a result counts as correct if it meets all of them. Each system is scored by precision@10: the share of its top 10 results that are correct.

    Interpreting the 99%

    The assistant filters on the same fields the test criteria come from, so when it converts a request correctly, every result qualifies. The score therefore mainly measures that conversion, which is exact for 98% of test searches. Most errors involve "management", which the job board uses both as a job category and as a seniority level. The test does not measure how well a job matches the topic within a broad category such as "Developer"; the answer step is meant to handle that.

    Without structured fields

    Many job sites have only the posting text. To test this case, an LLM reads each description and records the fields it states. This more than doubles precision compared with meaning search, but stays well below the version with structured fields because descriptions often leave the information out. Of the jobs with a salary, 85% state it in the description; for location the share is about half, and for contract type a third.

    Other results and limitations

    • The test searches are written by an LLM and interpreted by an LLM. Searches written by people have not been tested yet.
    • Only the first message is evaluated. Follow-ups and the written recommendations are not.
    • The job board's labels contain errors: in a manual check of 48 seniority labels, 88% were correct.
    • Typos and informal wording have little effect: 40 such searches score 99.7%, against 100% for the same searches written cleanly.
    • An answer costs about $0.002 in API calls. Building and evaluating the system cost about $5.
